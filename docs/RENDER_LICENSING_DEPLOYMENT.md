# Deploying MediHisaab Central Licensing System to Render

This step-by-step guide explains how to deploy the **Central Vendor Licensing API**, **Managed PostgreSQL Database**, and the **Public Download Portal** to [Render](https://render.com) using Infrastructure-as-Code (`render.yaml`).

---

## 2. Prerequisites

1. A [Render account](https://dashboard.render.com).
2. Git repository containing this codebase connected to Render.
3. An Ed25519 private signing key in PEM format.

### Generating Your Ed25519 Keypair (if not already created)
Run this command locally in Python:
```bash
python -c "
from cryptography.hazmat.primitives.asymmetric import ed25519
from cryptography.hazmat.primitives import serialization

key = ed25519.Ed25519PrivateKey.generate()
pem = key.private_bytes(
    encoding=serialization.Encoding.PEM,
    format=serialization.PrivateFormat.PKCS8,
    encryption_algorithm=serialization.NoEncryption()
).decode()

pub_bytes = key.public_key().public_bytes(
    encoding=serialization.Encoding.Raw,
    format=serialization.PublicFormat.Raw
).hex()

print('--- PRIVATE KEY PEM (Save in Render LICENSE_PRIVATE_KEY_PEM) ---')
print(pem)
print('--- PUBLIC KEY HEX (Must match client EMBEDDED_PUBLIC_KEY_HEX) ---')
print(pub_bytes)
"
```

## 3. Deployment using Render Blueprint (`render.yaml`)

The repository root includes a production-ready `render.yaml` specification.

### Step 1: Create a New Blueprint Instance
1. In the Render Dashboard, click **New +** $\rightarrow$ **Blueprint**.
2. Connect your Git repository.
3. Render automatically discovers `render.yaml` and displays three resources to build:
   * **`pharmacy-licensing-db`** (Managed PostgreSQL)
   * **`pharmacy-licensing-api`** (Python Web Service)
   * **`pharmacy-pos-portal`** (Static Site)
4. Click **Apply**.

---

## 4. Configuring Production Environment Variables

Once resources are provisioned, open **`pharmacy-licensing-api`** in the Render Dashboard $\rightarrow$ **Environment**:

| Environment Variable | Description | Value |
| :--- | :--- | :--- |
| `ENVIRONMENT` | Runtime environment | `production` |
| `DATABASE_URL` | Auto-populated by Render | Links automatically to `pharmacy-licensing-db` |
| `JWT_SECRET_KEY` | Auto-generated by Render | 64-character high-entropy secret |
| `JWT_ALGORITHM` | Token signing algorithm | `HS256` |
| `JWT_EXPIRY_MINUTES`| Token expiration | `60` |
| `CORS_ORIGINS` | Permitted web portal domains | `https://medihisaab.onrender.com,https://medihisaab-portal.onrender.com,https://pharmacy-pos-portal.onrender.com` |
| `LICENSE_PRIVATE_KEY_PEM` | **Ed25519 Private Key** | Paste full PEM string including header/footer |

> [!IMPORTANT]
> Paste the private key including `-----BEGIN PRIVATE KEY-----` and `-----END PRIVATE KEY-----`. Render securely encrypts this secret at rest.

## 5. First-Time Initialization & Verification

1. **Database Schema Auto-Creation:**
   On application startup, the service automatically executes schema initialization and seeds the default `OWNER` user and default commercial plans.
2. **Health Probe:**
   Visit `https://<your-service-subdomain>.onrender.com/health`.
   Verify the response:
   ```json
   {
     "status": "HEALTHY",
     "service": "pharmacy-licensing-service",
     "version": "1.0.0",
     "environment": "production",
     "database_connected": true
   }
   ```
3. **Log In to Vendor Portal:**
   Navigate to `https://<your-service-subdomain>.onrender.com/vendor` (or `/`).
   Sign in with:
   * **Email:** `owner@apexhealth.local`
   * **Password:** `OwnerSecurePass2026!`
4. **Change Default Credentials:**
   Update your password in the database or admin interface immediately upon initial setup.

---

## 6. Zero Operational Data Rule

Remember:
* **NEVER upload `pharmacy.db` from client machines to Render.**
* The Render database holds **only** vendor licensing metadata (client registration, plans, subscriptions, payment receipts, and issued license tokens).
* Pharmacies operate completely independent of the Render server during power or internet outages.
